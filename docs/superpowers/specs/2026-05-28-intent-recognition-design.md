## 一、问题分析

### 1.1 现状问题

| 问题 | 表现 |
|------|------|
| 意图不明确 | 用户不知道AI能回答什么，随便问导致答非所问 |
| 所有问题走同一流程 | 提分、志愿、风险都用同样的prompt模板 |
| 缺乏入口引导 | 学生首次使用不知道问什么 |

### 1.2 改造目标

1. **主动说明功能** — AI首次召唤时，主动告诉学生可以咨询哪些内容
2. **意图识别** — 区分问题类型，走不同的处理流程
3. **数据转述** — 把结构化数据交给LLM转述成自然语言

---

## 二、对话流程改造

### 2.1 改造前后对比

**现在：**
```
用户消息 → 查数据 → 构建Prompt → LLM回答
```

**改造后：**
```
用户消息 → 意图识别 → 规则匹配/LLM判断 → 查数据 → LLM转述 → 前端
```

### 2.2 首次召唤 vs 追问

| 场景 | 处理方式 |
|------|---------|
| 首次召唤（message_count == 0） | AI主动说明功能，询问想了解什么 |
| 追问（message_count > 0） | 意图识别 → 查数据 → LLM转述 |

## 三、意图识别设计

### 3.1 意图类型

| 类型 | 关键词 | 回答格式 |
|------|--------|---------|
| 提分咨询 | 加X分、概率提升、能上什么学校 | 直接给数值变化 |
| 志愿选择 | 选哪个、哪所、怎么选 | A/B/C选项 |
| 风险分析 | 为什么、原因、为什么下滑 | 一句话分析原因 |
| 学习画像 | 学习特点、强项弱项、我是哪种 | 特点描述 |
| 综合分析 | 分析一下、怎么样、全面看 | 结构化总结 |

### 3.2 识别流程

```
用户消息
    ↓
规则匹配（关键词命中）
    ↓
命中 → 返回意图类型
未命中 → LLM判断意图类型
    ↓
返回 {intent: "提分咨询", confidence: 0.9}
```

### 3.3 规则定义

```python
INTENT_PATTERNS = {
    "提分咨询": ["加", "分", "概率", "提升", "能上", "考上"],
    "志愿选择": ["选", "哪个", "哪所", "怎么选", "冲", "保底", "稳定"],
    "风险分析": ["为什么", "原因", "下滑", "下降", "波动", "不好"],
    "学习画像": ["学习", "特点", "强项", "弱项", "类型", "风格"],
    "综合分析": ["分析", "看看", "怎么样", "情况", "评估", "全面"],
}
```

### 3.4 LLM意图判断（规则未命中时）

当规则匹配不到时，让LLM判断意图：

```
你是一个意图分类器。根据用户问题，判断属于哪种类型。

类型：提分咨询、志愿选择、风险分析、学习画像、综合分析

用户问题：{user_message}

只返回一个词：提分咨询 / 志愿选择 / 风险分析 / 学习画像 / 综合分析
```

## 四、功能说明设计

### 4.1 首次召唤欢迎语

当学生第一次召唤AI时（message_count == 0 且无具体问题），返回：

```
你好！我是升学预测小助手，我可以帮你分析：

📊 成绩定位 — 看看你的分数能上什么学校
🎯 志愿选择 — 冲刺/稳定/保底怎么选
📈 提分建议 — 加多少分能提升录取概率
⚠️ 风险提示 — 哪些科目需要重点关注
📝 学习画像 — 了解你的学习特点

你想了解哪个？（直接说序号或问题）
A. 成绩定位
B. 志愿选择
C. 提分建议
D. 风险提示
E. 学习画像
```

### 4.2 追问时的处理

当用户追问时，先识别意图，再根据类型查数据：

| 意图 | 查什么数据 | 怎么回答 |
|------|-----------|---------|
| 提分咨询 | simulation数据 | "加10分后，第三中学概率从71%提升到81%" |
| 志愿选择 | predictions数据 | 给出A/B/C选项 |
| 风险分析 | risk数据 | "数学近3次波动较大，建议加强" |
| 学习画像 | portrait数据 | "你是稳定型学习者，理科较强" |
| 综合分析 | 所有数据 | 结构化输出所有维度 |
