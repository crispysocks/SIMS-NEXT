# 当前限制与修复路径

## 1. 难度启发式估计

难度等级（easy / medium / hard）按模板静态分配——系数小 → 简单，数值范围大 → 困难。未经过实际学生成绩数据的经验校准。

**后果：**一个"中等"的二次方程可能比"困难"的一次方程更难。跨知识点难度不可比较。

**修复路径：**收集答题日志，拟合项目反应理论（IRT）模型，根据实际通过率重新标注模板难度。

## 2. 无大规模校准

所有模板参数（系数范围、根约束）均为手工选择。15 个模板通过 SymPy 正确性测试验证，未经过学生试验。

**后果：**模板可能生成过于简单、过于困难或心理上缺乏吸引力的题目。没有数据来调优生成器。

**修复路径：**让真实学生使用系统，记录每个模板的正确率，调整参数范围使各难度层级分别达到约 70% / 50% / 30% 的正确率。

## 3. 知识点图谱有限

仅覆盖 5 个知识点，前置依赖树深度最大为 2。每个知识点使用独立 Beta 分布——无共享知识迁移，无层次化技能模型。

**后果：**掌握"一元一次方程"不会加速"求导"的学习，尽管两者都涉及代数操作。系统将它们视为无关知识点。

**修复路径：**引入层次贝叶斯模型，使父知识点与子知识点共享先验信息，或添加显式的跨知识点技能标签。

## 4. 无长期记忆持久化

所有状态存储在内存中（`MasteryStore._states` 为普通 `dict`）。刷新浏览器或重启服务器将丢失全部进度。

**后果：**辅导系统无法跨天或跨周追踪学习情况。每次会话都从 Beta(3,3) 先验开始。

**修复路径：**添加 `MasteryStore.save(path)` / `MasteryStore.load(path)`，使用 JSON 序列化 `MasteryState` 字段。无需数据库——每个学生一个文件即可满足 MVP+1 需求。

## 5. 仅支持单变量

所有题目使用单一变量 `x`。没有多元微积分、几何或文字题。

**后果：**无法测试涉及 y、z 或参数方程的场景，限制了高年级数学的适用性。

**修复路径：**扩展引擎支持多符号变量，先加 `y`，再扩展至参数 `a、b、k`。

## 6. 答案格式敏感

验证器期望特定格式——二次方程求根必须用逗号分隔（`-1,-4`），因式分解必须写成展开形式。等价但格式不同的表达式可能被误判。

**后果：**`x=-1, x=-4` 或 `-1 and -4` 这样的答案可能被标记为错误，给学生带来挫败感。

**修复路径：**在 `safe_compare` 中添加格式规范化层，将常见替代格式转换为标准格式后再比较。
